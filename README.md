Лабораторная работа №2 — Мини-СУБД на Java

1. Что это

Консольная СУБД с поддержкой основных операций (INSERT, SELECT, UPDATE,
DELETE), связями между таблицами через PRIMARY KEY / FOREIGN KEY и
индексированием через TreeMap.

Всё хранится в папке db_data/ рядом с приложением — файлы .ser
(стандартная сериализация Java).

2. Как запустить

Нужна JDK 11 или новее. Проверить: java -version.

    cd SimpleDBMS
    javac SimpleDBMS.java
    java SimpleDBMS

Или в IntelliJ / VS Code — открыть папку и нажать Run над main.

Если java/javac не в PATH — поставить Temurin 17 с https://adoptium.net.

3. Как пользоваться

После запуска приглашение sql>. Команды заканчиваются на ;.
Если нужен перенос строки — приглашение сменится на ->, значит
программа ждёт продолжения.

Основные команды:

- HELP; — список всех команд
- SHOW TABLES; — что уже есть в базе
- SELECT * FROM cars;
- INSERT INTO cars VALUES (4, 'Audi', 55000.0, TRUE, 1);
- UPDATE cars SET price = 50000 WHERE id = 4;
- DELETE FROM cars WHERE id = 4;
- CREATE INDEX idx_cars_price ON cars (price);
- BENCHMARK; — автобенч на 50 000 строк
- EXIT; — выход (данные сохраняются)

При первом запуске создаются демо-таблицы brands и cars
со связанными строками — чтобы было что показать.

4. Архитектура

Основные классы:

    SimpleDBMS                  — main + enum DataType
    ├── Engine                  — парсинг SQL и выполнение
    ├── Store                   — сохранение/загрузка .ser
    ├── Table                   — одна таблица (столбцы + строки)
    │   ├── Column              — метаданные столбца
    │   └── Row                 — одна запись (Map<имя, значение>)
    ├── TableIndex              — индекс на TreeMap
    └── RowIterator             — итератор по строкам

Паттерны:

- Repository (Store) — работа с файлами спрятана, Engine про диск не знает
- Iterator (RowIterator) — обход строк без раскрытия внутреннего Map
- разделение слоёв — Engine только про SQL, Store только про файлы

4.1. Как проходит INSERT

    ввод строки
       ↓
    main() копит до ';'
       ↓
    Engine.execute() → Engine.insert()
       ↓
    1. парсит колонки и кортежи
    2. для КАЖДОЙ строки:
         - парсит значения по типам
         - проверяет FK (есть ли значение в родителе)
         - проверяет PK на дубликат (в т.ч. внутри этой же пачки)
    3. если всё ок — коммитит строки в таблицу
    4. обновляет все индексы
    5. Store.saveTable() + Store.saveIndex()

Проверки идут до коммита — если в пачке из 5 записей упадёт 4-я,
первые 3 не останутся в памяти без сохранения на диск.

4.2. Как проходит SELECT с индексом

    Engine.select()
       ↓
    если WHERE по индексированному столбцу:
        TableIndex.search(op, val)
            → TreeMap.headMap / tailMap → O(log n)
       ↓
    по полученным PK достаём строки из Table.rows
       ↓
    formatTable() рисует ASCII-таблицу

В выводе печатается план: [index idx_cars_brand, строк: 1] —
видно, что реально использовался индекс, а не full scan.

5. Результаты бенчмарка

BENCHMARK; генерирует 50 000 строк, делает 100 SELECT'ов без индекса
и 100 с индексом. Замеры на MacBook Air M4 (Apple Silicon), JDK 27, SSD:

    генерация+сохранение: 190,0 ms
    построение индекса:    39,4 ms
    SELECT без индекса:   2,022 ms
    SELECT с индексом:    0,052 ms
    ускорение:            x38,7

Индекс ускоряет точечный поиск примерно в 40 раз на 50 000 записей.
На маленьких таблицах (десятки-сотни строк) разница почти не видна —
индекс начинает окупаться от нескольких тысяч записей.

6. Ограничения

- FK ссылается только на PK родителя, не на произвольный UNIQUE-столбец
- WHERE — только одно условие, без AND/OR
- INSERT не переживёт ")" внутри строкового литерала ('Toyota (Camry)')
- JOIN — только INNER по равенству двух столбцов
- если имена столбцов в двух таблицах совпадают, в JOIN без
  префикса table.col значение правой таблицы перетирает левую
- пакетное удаление связанных записей одним DELETE не работает
  (проверка FK сработает на второй записи, которую ещё не удалили)

7. Что проверял

Запускал на JDK 27 (macOS, Apple Silicon M4). Прошёл все команды из HELP.
Отдельно проверил:

- перезапуск — таблицы и индексы подгружаются с диска
- удаление родителя с зависимыми строками — падает с ошибкой
- INSERT с дубликатом PK в одном запросе — откатывается целиком
- BENCHMARK — для WHERE по индексированному полю план index,
  без индекса — full scan
